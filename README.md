# REST-сервис для агрегации онлайн-подписок

Реализация бэкенд-сервиса для управления и агрегации данных об онлайн-подписках пользователей. Тестовое задание для компании **Effective Mobile**.

## Стек технологий
* **Язык разработки:** Go (Golang)
* **Роутер:** Chi (v5)
* **СУБД:** PostgreSQL + драйвер pgx (v5)
* **Миграции:** Чистый SQL (автоматически применяются при старте приложения)
* **Документация:** Swagger (swaggo/http-swagger)
* **Контейнеризация:** Docker, Docker Compose

---

## Архитектура проекта
Проект спроектирован с упором на принципы SOLID и разделение ответственности (Clean Architecture):
* `cmd/api/main.go` — точка входа, считывание конфигурации, инициализация зависимостей и запуск HTTP-сервера.
* `internal/config/` — модуль конфигурации приложения, работающий с переменными окружения через `.env`.
* `internal/domain/` — слой доменных моделей и структур данных подписок.
* `internal/handler/` — HTTP-слой (контроллеры, валидация входящих запросов, аннотации для Swagger).
* `internal/usecase/` — слой бизнес-логики сервиса.
* `internal/repository/` — слой работы с базой данных (SQL-запросы к PostgreSQL и логика применения миграций).
* `migrations/` — SQL-файлы для инициализации и настройки структуры БД.

---

## Требования из ТЗ, реализованные в проекте
1. **CRUDL-операции:** Полный цикл управления подписками (создание, чтение, обновление, удаление, вывод списка).
2. **Структура записи:** Хранение названия сервиса, цены (целое число рублей), `user_id` (UUID), даты начала и опциональной даты окончания.
3. **Агрегация:** Отдельная ручка для подсчета суммарной стоимости подписок за выбранный период с возможностью фильтрации по конкретному пользователю и названию сервиса.
4. **Миграции:** Автоматический накат таблиц при первом запуске базы данных.
5. **Логирование:** Все ключевые этапы работы приложения и HTTP-запросы покрыты логами.
6. **Конфигурация:** Все чувствительные данные вынесены в файл параметров окружения `.env`.
7. **Документация:** Полноценный интерактивный Swagger UI.

## Как запустить проект

Для запуска всего окружения вам понадобятся только установленные Docker и Docker Compose.

1. **Клонируйте репозиторий и перейдите в него:**
```bash
   git clone https://github.com/Nana-31/effective_mobile_test.git
   cd test_em
   ```

2. **Запустите проект одной командой:**
```bash
   docker compose up --build
```

После этого Docker автоматически скачает PostgreSQL, применит файлы миграций из папки migrations, соберет Go-приложение и запустит веб-сервер на порту :8080.

## Документация API (Swagger)

После того как контейнеры успешно запустятся, интерактивная документация со всеми эндпоинтами будет доступна в браузере по адресу:
http://localhost:8080/swagger/index.html

**Список доступных эндпоинтов в Swagger UI:**

POST /subscription/create — Добавление новой подписки пользователю.
GET /subscription — Получение информации о конкретной подписке.
PUT /subscription/update — Обновление параметров существующей подписки.
DELETE /subscription/delete — Удаление записи о подписке.
GET /subscription/list — Получение списка всех подписок.
GET /subscription/total — Подсчет суммарной стоимости всех подписок за выбранный период с фильтрацией по user_id и service_name.
